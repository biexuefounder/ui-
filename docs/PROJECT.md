# 项目说明：界面研习录

最后更新：2026-10-24。本文记录已确认需求与当前实现；实际代码和远程最新提交优先于旧的状态描述。

## 目标与边界

用户希望利用 Codex 云端持续研究优秀网站，在一个可检索的网站里积累成果，供自己以后学习设计与前端开发。项目可公开，但初期不面向他人运营。这是独立的案例库，不是用户的四级学习毕设“语境之外”，不要混入其题库或学习管理功能。

读者掌握 HTML、CSS、基础 JS。中文讲解为主，术语附英文，代码保留原名，陌生语法和依赖要解释。先展示整站结构，让读者自由进入页面或组件；重点深入前端，后端等说明作用和联系。

## 已确认产品要求

- 按设计问题查找案例，而不是仅按网站名称堆积书签。
- 第一批研究整站导航、信息层级、阅读布局；总体关注教育学习工具和视觉、动效鲜明的网站。
- 优先有开源代码或官方技术说明的案例。保留原网站、仓库和官方文档链接。
- 分析涵盖视觉、体验、实现思路、适用场景与局限。事实、分析判断、推测必须区分。
- 原项目入口与站内局部演示结合；演示优先原生 HTML/CSS/JS，注明与原实现的区别。
- 浅色文档风格、留白充足，电脑和平板都能阅读和操作。
- 同类案例没有明显差异就不收录；检查不通过可以跳过当期，记录原因。
- 每周日北京时间10:00计划准备3个候选，用户选择后启动；有待验收成果时不追加。定时任务尚未启用。
- 每次提供五分钟摘要加体验，用户接受后才合并发布；两个云端账号不固定分工，不为用完额度制造内容。

## 当前完成状态

源码已上传 `biexuefounder/ui-` 的 `main`。当前正式案例为 VitePress，包含七个章节及导航局部演示。已有主题筛选、标题/标签搜索、案例地图、章节锚点、演示宽窄切换和源码下载。

无服务端、数据库、账号系统、npm依赖、构建步骤或AI API调用。案例直接保存在版本化的JS文件中。`dist/` 虽名为dist，当前就是手写源文件目录，不是可以删除重建的临时构建产物。

## 运行与数据流

在仓库根目录执行：

```sh
node scripts/check.mjs
python -m http.server 8000 --directory dist
```

浏览器访问 `http://localhost:8000/`。不需要 `npm install` 或 `npm run build`；仓库没有 `package.json`。Python只提供本地静态预览，不是生产后端。

`index.html` 先加载 `data.js`，再加载 `app.js`。后者监听 `hashchange`，按路由渲染内容：

| 地址片段 | 页面 |
| --- | --- |
| 空hash或 `#` | 索引 |
| `#topic/整站导航` | 对应主题筛选，生成链接时编码中文 |
| `#case/vitepress` | 案例详情 |
| `#case/vitepress/demo` | 案例中指定章节 |
| `#method` | 收录方法 |

搜索作用于案例名称、标题和标签，不是全文搜索；筛选与搜索共同生效。搜索状态在内存中，刷新会重置。章节切换使用现有DOM滚动，同一案例内不会重新创建全部内容。演示在隔离iframe中运行。

## 数据结构

`ATLAS_CASES` 中每项包含：

| 字段 | 形状与约定 |
| --- | --- |
| `id` | 唯一稳定字符串，用小写英文和连字符，参与URL |
| `name`, `title`, `summary` | 项目名、案例标题、摘要 |
| `tags` | 设计问题字符串数组；筛选使用精确匹配 |
| `date` | 分析日期，`YYYY-MM-DD` |
| `sources` | `[显示名称, https地址]` 的数组 |
| `sections` | 章节数组，各项有 `id`, `title`, `subtitle`, `html` |

`sections[].html` 是可信维护者编辑的HTML，会直接渲染。不能把未经审核的抓取内容或用户输入直接插入。代码示例在HTML里要转义 `<`、`>`、`&`；JS模板字符串内的反引号和 `${...}` 也需正确处理。新增案例保持唯一ID；不要随意改动已存在的链接。

## 当前局限与后续优先级

以下是已发现的实现限制，不代表已经修复：

1. 索引案例数、不同标签数、不同iframe源地址数、侧栏数量和详情编号已从数据派生；共享同一演示地址只计一次。主题包含预设主题及案例新增标签。
2. 所有案例共用一张CSS示意图；它不是原站截图。不要把它描述为真实网站画面。
3. 演示控制器使用 `desktop-demo`、`tablet-demo`、`demo-wrap` 固定ID。每个详情目前适配一组控件；新增不同演示时保持契约或改为数据属性绑定。
4. `navigation.html` 内联了演示JS，`navigation.js` 是同逻辑的下载副本。修改时保持两份一致，或另行建立生成机制。
5. 检查脚本只对指定的三个JS文件运行语法检查，新增演示脚本和HTML内联脚本需额外检查。脚本不验证外链可访问性、文章准确性和浏览器交互。
6. 收录方法页已同步日常任务规则；侧栏主导航、主题选中状态和面包屑随路由更新。
7. 物理平板尚未实测；当前记录包括桌面与窄屏演示测试，不等于所有设备验证完毕。
8. 定时研究、两个账号协作和GitHub Pages成功部署均未验证启用。

先解决影响扩展和真实使用的问题，再扩充案例；不要仅为架构整齐迁移到大型框架。
