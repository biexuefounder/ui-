## 任务状态与积压规则

候选待选择 → 用户选择并启动 → 进行中 → 待验收 → 用户接受 → 合并发布 → 回读确认。

在 docs/runs.md 登记进行中和待验收成果，附分支或 PR。准备任务同时检查最新记录和可访问的 PR 状态；状态无法核实时先说明，不推断已验收。有进行中或待验收成果时优先报告进展、阻碍与需要用户判断的点，不追加新候选。证据不足不收录；受阻时完成独立部分并报告缺口，不擅自换选题。

## 每周准备：可直接使用的任务指令

> 阅读 AGENTS.md、docs/PROJECT.md、docs/automation.md、docs/runs.md 和 dist/data.js，核对当前任务与待验收状态。有进行中或待验收成果时，仅提供进展提醒和下一步，不新增选题。否则准备3张简短候选卡，优先系统补齐基础，避免重复已有案例。每张包含：学习问题、候选网站或维护待办、补齐的空缺、预期成果、可核查来源及访问状态。标出首选和理由。候选网站须实际查阅官方或开源来源；不可访问时明确标注。只准备候选，等待用户选择后才开展完整任务，不写入正式案例、不合并或发布。结果返回任务会话；未另行授权不发送邮件或其他消息。

候选卡模板：编号与标题 / 学习问题 / 网站或待办 / 与已有内容的差异 / 预期成果 / 来源与访问状态 / 推荐理由。

## 用户选择后：执行指令

> 执行我选定的候选，读取仓库规则和最新main，保留已有工作，使用独立分支。每次只做一个任务。案例先说明整站结构，再讲透一个设计问题，提供官方依据、关键源码路径、陌生术语解释、一个原创原生交互演示及适用边界。区分事实、分析判断和教学复现。完成结构检查、来源核查、电脑和平板宽度下的搜索、筛选、导航、演示、键盘及下载验证。失败要诊断，缺口如实记录，证据不足不收录。完成后提供分支或 PR 和五分钟验收包，等待用户接受后才合并发布。

## 五分钟验收包

- 一分钟：改了什么、为什么值得学、影响哪些页面。
- 三分钟：最多3条具体体验步骤，写明预期现象。
- 一分钟：已执行检查、未验证项和需要决定的取舍。
- 附分支/PR、当前状态；用户可回复“接受”“修改：…”或“暂缓”。接受前不合并、不发布。

## 发布与协作

当前独立站点 https://interface-atlas-study.merrywand12.chatgpt.site 不随仓库提交自动变化。仓库现有 Pages 工作流在main推送时尝试部署，因此合并前必须已有发布授权；发布完成还需回读验证。Pages是否启用、定时准备是否启用分别记录，不混为一谈。

不申请收费 API，不复制会话或凭证。两个账号不同时编辑同一分支；需要时错开任务并在合并前复核最新main。
